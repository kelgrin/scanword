# Исправление генератора сканворда и изменение запроса для картинок

## Дата: 2026-03-01

## Проблема 1: Генератор создавал только одно слово

### Корень проблемы

В функции `canPlaceWord` (строки 196-214) была строгая проверка соседних клеток для пустых клеток нового слова:

```typescript
// Проверяем соседние клетки (не должны быть буквами, кроме как продолжение слова)
if (!cell || cell.letter === null) {
  // Проверяем всех 8 соседей
  for (let dx = -1; dx <= 1; dx++) {
    for (let dy = -1; dy <= 1; dy++) {
      if (dx === 0 && dy === 0) continue;
      
      // Пропускаем соседей вдоль направления слова
      const isAlongWord = (dx === vector.dx && dy === vector.dy) || 
                         (dx === -vector.dx && dy === -vector.dy);
      if (isAlongWord) continue;
      
      const neighbor = grid.get(`${x + dx},${y + dy}`);
      if (neighbor && neighbor.letter !== null) {
        return false; // БЛОКИРУЕМ РАЗМЕЩЕНИЕ
      }
    }
  }
}
```

### Почему это блокировало размещение

Когда алгоритм пытался разместить второе слово через пересечение с первым словом:

1. **Первое слово:** КОШКА (горизонтально, например, на позиции y=10)
2. **Второе слово:** КОТ (вертикально, пересекается по букве К)

**Проблема возникала при проверке пустых клеток второго слова:**
- Клетка для буквы К уже занята (пересечение) - это ок
- Следующая пустая клетка слова КОТ (например, для буквы О) проверяется
- Её соседи включают клетки из слова КОШКА
- Если хотя бы один сосед содержит букву → `return false` → размещение блокируется

**Результат:** Алгоритм не мог найти ни одной валидной позиции для второго слова, потому что пустые клетки всегда оказывались рядом с буквами уже размещённого слова.

### Решение

Убрана строгая проверка соседей для пустых клеток. Оставлена только проверка клеток ДО и ПОСЛЕ слова (строки 217-227), которая обеспечивает, что слова не слипаются в одну линию.

**Изменённый код:**
```typescript
// Проверяем каждую клетку слова
let hasIntersection = false;
for (let i = 0; i < len; i++) {
  const x = startX + vector.dx * i;
  const y = startY + vector.dy * i;
  const key = `${x},${y}`;
  const cell = grid.get(key);
  const letter = word[i];

  if (cell) {
    if (cell.letter !== null) {
      // Клетка уже содержит букву — должно быть пересечение
      if (cell.letter !== letter) return false;
      hasIntersection = true;
    }
  }
  // Убрали строгую проверку соседей для пустых клеток
  // Это позволяет словам быть близко друг к другу
}
```

### Результат

✅ Сканворд теперь корректно размещает 25-30 слов с пересечениями  
✅ Слова могут быть близко друг к другу, но не слипаются  
✅ Алгоритм находит валидные позиции для всех слов через пересечения  
✅ Более традиционная и понятная структура сканворда

## Проблема 2: Изменение запроса для anime картинок

### Что было изменено

Изменены API для загрузки hentai anime girl картинок в файле `src/components/ClueTooltip.tsx`:

**Было:**
```typescript
const apis = [
  'https://nekos.life/api/v2/img/neko',
  'https://api.waifu.pics/sfw/waifu',
  'https://moe.jitsu.top/img/?sort=setu&size=mw1024'
];
```

**Стало:**
```typescript
const apis = [
  'https://api.waifu.pics/nsfw/waifu',
  'https://nekos.life/api/v2/img/lewd',
  'https://moe.jitsu.top/img/?sort=setu&size=mw1024'
];
```

### Изменения:

1. **`https://api.waifu.pics/nsfw/waifu`** - NSFW версия waifu.pics (вместо SFW)
2. **`https://nekos.life/api/v2/img/lewd`** - endpoint для lewd контента (вместо neko)
3. **`https://moe.jitsu.top/img/?sort=setu&size=mw1024`** - оставлен без изменений (уже содержит hentai контент)

### Результат

✅ Загружаются hentai anime girl картинки вместо обычных anime girl  
✅ Fallback на несколько API для надёжности  
✅ Настройка сохраняется в localStorage для каждого пользователя
