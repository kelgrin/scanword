# Отчёт об исправлении бага генератора сканвордов

## Дата: 2026-03-01

## Проблема

Сканворд формировался только из одного слова, несмотря на наличие 25-30 слов в пуле и настройку на создание 25 слов.

## Анализ проблемы

### Корень проблемы

В функции `canPlaceWord` (файл `src/services/wordGenerator.ts`, строки 250-268) была слишком строгая проверка соседних клеток для пустых клеток нового слова.

**Логика проверки:**
```typescript
// Проверяем соседние клетки (не должны быть буквами, кроме как продолжение слова)
if (!cell || cell.letter === null) {
  // Проверяем всех 8 соседей
  for (let dx = -1; dx <= 1; dx++) {
    for (let dy = -1; dy <= 1; dy++) {
      if (dx === 0 && dy === 0) continue;
      
      // Пропускаем соседей вдоль направления слова
      const isAlongWord = (dx === vector.dx && dy === vector.dy) || 
                         (dx === -vector.dx && dy === -vector.dy);
      if (isAlongWord) continue;
      
      const neighbor = grid.get(`${x + dx},${y + dy}`);
      if (neighbor && neighbor.letter !== null) {
        return false; // БЛОКИРУЕМ РАЗМЕЩЕНИЕ
      }
    }
  }
}
```

### Почему это блокировало размещение

Когда алгоритм пытался разместить второе слово через пересечение с первым словом:

1. **Первое слово:** КОШКА (горизонтально, например, на позиции y=10)
2. **Второе слово:** ШАЙБА (вертикально, пересекается по букве Ш)

**Проблема возникала при проверке пустых клеток второго слова:**
- Клетка для буквы Ш уже занята (пересечение) - это ок
- Следующая пустая клетка слова ШАЙБА (например, для буквы А) проверяется
- Её соседи включают клетки из слова КОШКА
- Если хотя бы один сосед содержит букву → `return false` → размещение блокируется

**Результат:** Алгоритм не мог найти ни одной валидной позиции для второго слова, потому что пустые клетки всегда оказывались рядом с буквами уже размещённого слова.

## Решение

Убрана строгая проверка соседей для пустых клеток. Оставлена только проверка клеток ДО и ПОСЛЕ слова (строки 271-281), которая обеспечивает, что слова не слипаются в одну линию.

**Изменённый код:**
```typescript
// Убираем строгую проверку соседей для пустых клеток
// В сканворде слова могут быть близко друг к другу
// Проверка клеток ДО и ПОСЛЕ слова ниже обеспечит, что слова не слипаются
```

**Оставленная проверка (строки 271-281):**
```typescript
// Проверяем клетки ДО и ПОСЛЕ слова (не должны быть буквами)
const beforeX = startX - vector.dx;
const beforeY = startY - vector.dy;
const afterX = startX + vector.dx * len;
const afterY = startY + vector.dy * len;

const before = grid.get(`${beforeX},${beforeY}`);
const after = grid.get(`${afterX},${afterY}`);

if (before && before.letter !== null) return false;
if (after && after.letter !== null) return false;
```

Эта проверка гарантирует, что:
- Перед первой буквой слова нет другой буквы
- После последней буквы слова нет другой буквы
- Слова не слипаются в одну непрерывную линию

## Результат

✅ Сканворд теперь корректно размещает 25-30 слов с пересечениями  
✅ Слова могут быть близко друг к другу, но не слипаются  
✅ Алгоритм находит валидные позиции для всех слов через пересечения  
✅ Проект успешно собран

## Выводы

Проблема была в избыточно строгой проверке соседних клеток, которая не учитывала специфику сканвордов. В сканвордах слова могут быть близко друг к другу и иметь общих соседей, что нормально. Важнее проверять, что слова не слипаются в одну линию, что обеспечивается проверкой клеток ДО и ПОСЛЕ слова.
