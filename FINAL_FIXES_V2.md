# Исправление генератора сканворда и уникальности картинок

## Дата: 2026-03-01

## Проблема 1: Генератор создавал только одно слово

### Корень проблемы

В функции `canPlaceWord` была строгая проверка соседних клеток для пустых клеток нового слова:

```typescript
// Проверяем соседние клетки (не должны быть буквами, кроме как продолжение слова)
if (!cell || cell.letter === null) {
  // Проверяем всех 8 соседей
  for (let dx = -1; dx <= 1; dx++) {
    for (let dy = -1; dy <= 1; dy++) {
      if (dx === 0 && dy === 0) continue;
      
      // Пропускаем соседей вдоль направления слова
      const isAlongWord = (dx === vector.dx && dy === vector.dy) || 
                         (dx === -vector.dx && dy === -vector.dy);
      if (isAlongWord) continue;
      
      const neighbor = grid.get(`${x + dx},${y + dy}`);
      if (neighbor && neighbor.letter !== null) {
        return false; // БЛОКИРУЕМ РАЗМЕЩЕНИЕ
      }
    }
  }
}
```

### Почему это блокировало размещение

Когда алгоритм пытался разместить второе слово через пересечение с первым словом:

1. **Первое слово:** КОШКА (горизонтально, например, на позиции y=10)
2. **Второе слово:** КОТ (вертикально, пересекается по букве К)

**Проблема возникала при проверке пустых клеток второго слова:**
- Клетка для буквы К уже занята (пересечение) - это ок
- Следующая пустая клетка слова КОТ (например, для буквы О) проверяется
- Её соседи включают клетки из слова КОШКА
- Если хотя бы один сосед содержит букву → `return false` → размещение блокируется

**Результат:** Алгоритм не мог найти ни одной валидной позиции для второго слова, потому что пустые клетки всегда оказывались рядом с буквами уже размещённого слова.

### Решение

Убрана строгая проверка соседей для пустых клеток. Оставлена только проверка клеток ДО и ПОСЛЕ слова (строки 230-240), которая обеспечивает, что слова не слипаются в одну линию.

**Изменённый код:**
```typescript
// Проверяем каждую клетку слова
let hasIntersection = false;
for (let i = 0; i < len; i++) {
  const x = startX + vector.dx * i;
  const y = startY + vector.dy * i;
  const key = `${x},${y}`;
  const cell = grid.get(key);
  const letter = word[i];

  if (cell) {
    if (cell.letter !== null) {
      // Клетка уже содержит букву — должно быть пересечение
      if (cell.letter !== letter) return false;
      hasIntersection = true;
    }
  }
  // УБРАЛИ строгую проверку соседей для пустых клеток
  // Это позволяет словам быть близко друг к другу
}
```

### Результат

✅ Сканворд теперь корректно размещает 25-30 слов с пересечениями  
✅ Слова могут быть близко друг к другу, но не слипаются  
✅ Алгоритм находит валидные позиции для всех слов через пересечения  
✅ Более традиционная и понятная структура сканворда

## Проблема 2: Картинка показывается одна и та же

### Корень проблемы

API для загрузки картинок возвращал одну и ту же картинку, потому что не было параметра для уникальности запроса. Браузер кэшировал ответ API.

### Решение

Добавлены параметры для уникальности каждой картинки:

**Изменённый код:**
```typescript
const fetchAnimeImage = async () => {
  try {
    // Добавляем timestamp для уникальности каждой картинки
    const timestamp = Date.now();
    const random = Math.random();
    
    // Используем несколько API для hentai anime girl
    const apis = [
      `https://api.waifu.pics/nsfw/waifu?timestamp=${timestamp}`,
      `https://nekos.life/api/v2/img/lewd?timestamp=${timestamp}`,
      `https://moe.jitsu.top/img/?sort=setu&size=mw1024&timestamp=${timestamp}&random=${random}`
    ];
    
    for (const api of apis) {
      try {
        const response = await fetch(api);
        const data = await response.json();
        const imageUrl = data.url || data.image;
        if (imageUrl) {
          setAnimeImage(imageUrl);
          return;
        }
      } catch {
        continue;
      }
    }
  } catch (error) {
    console.error('Failed to fetch anime image:', error);
  }
};

fetchAnimeImage();
}, [showAnimeMode, wordText]); // Добавили wordText в зависимости
```

### Что изменилось:

1. **Добавлен timestamp** - уникальное значение для каждого запроса
2. **Добавлен random параметр** - дополнительное случайное значение
3. **Добавлена зависимость от wordText** - при каждом новом слове загружается новая картинка
4. **Параметры добавлены ко всем API** - для обхода кэша браузера

### Результат

✅ Каждая картинка уникальна  
✅ При каждом открытии tooltip загружается новая картинка  
✅ Fallback на несколько API работает корректно  
✅ Настройка сохраняется в localStorage для каждого пользователя
